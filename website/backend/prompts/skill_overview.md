## Skill 概要

本網頁的 Skill 端使用專題中開發的 **ORQA Formulation Skill**（`orqa-formulation-mcq-2`）。它原本是為 ORQA（Operations Research Question Answering）四選一題目設計的「推理手冊」，教模型先從商業情境中**重建最佳化模型**，再回答關於模型的問題。

Baseline 端使用相同的模型與輸出格式規則，但沒有載入這份 Skill，因此兩邊的差異來自 Skill 本身。

## 核心觀念

情境描述是一段商業敘述，裡面**沒有數學式**；題目問的卻是一個從未寫出來的數學模型。所以不論題型，步驟都一樣：

1. **重建模型**：找出集合、參數、決策變數、目標函數與限制式。
2. **從模型讀出答案**：回答題目問的那一部分。

不要直接從文字比對答案：大多數錯誤選項都是「對情境而言為真、對模型而言為假」的敘述。

## 分析流程

| 階段 | 內容 |
|---|---|
| Step 0：重建模型 | 集合（模型以什麼為索引）、參數（求解前已知的數字）、決策變數（決策者要選的東西）、目標與限制 |
| Step 1：判斷題型 | 依題目敘述對應到 11 種題型（目標、限制式、問題類別、模型類型、集合、決策變數、目標中的參數 / 變數、限制式左式、限制式作用對象等） |
| Step 2：各題型的檢查程序 | 例如利潤 = 收入 − 成本、「盡快完成」代表最小化最大完成時間、容量限制要依資源逐一寫出、限制式的自由索引就是它的作用對象 |
| 自我檢查 | 回答的是模型還是文字？參數與變數有沒有搞混？哪個索引是自由的、哪個被加總？ |

## 參考文件

- **Model types**：判斷 LP / ILP / MILP / MINLP 的決策程序（依變數型態與代數形式，而非直覺）。
- **Problem categories**：依結構判斷問題類別（指派、混合、路徑、排程、批量、網路流等），不受產業用語影響。
- **Constraint anatomy**：「對每個 i，∑ over j ≤ 上限(i)」的結構——自由索引與被加總索引的區分。

## 在本網頁中的使用方式

原 Skill 的輸出規則是「只輸出一個選項字母」。為了用在沒有選項的自由提問，本網頁在 Skill 前加上一段簡短的使用說明：保留 Skill 完整的建模方法，但改為輸出結構化的解答，依序包含：

1. 問題理解
2. 模型元素（集合、參數、決策變數及其型態）
3. 目標函數與限制式
4. 模型類型與求解方法
5. 求解與驗證
6. 假設與限制
7. 結論

Skill 的原始內容沒有被修改；若要替換成其他 Skill，只需修改後端 `config.yaml` 中的 `prompts.skill_source`。
