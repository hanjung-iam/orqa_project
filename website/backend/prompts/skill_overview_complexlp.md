## Skill 概要

**Practical Implementation**（原始 Skill：`complexlp-v2`，ComplexLP v2）是為「算出最佳值」的數值型最佳化題目設計的解題手冊，例如飲食規劃、生產組合、混合、運輸／轉運、設施選址、最大流、TSP、生產與存貨規劃。它要求模型完整建模、以手算精確求解，並證明答案可行且最佳。

與 Concept Identification 不同：Concept Identification 著重**辨認模型結構**（目標、限制式、參數、模型類型），Practical Implementation 著重**把模型解出來並驗證**。

## v2 的三項核心規則

| 規則 | 內容 |
|---|---|
| 題目獨立性 | 每一題都從當前題目的資料重新解析、建模、計算與驗證，不沿用其他題目的答案或結構。 |
| 禁止未驗證的捷徑 | 捷徑只能縮減計算，不能取代最佳性證明。例如最大流要同時給出可行流與最小割，TSP 不能只找到一條較短路徑就宣稱最優。 |
| 整數（完整單位）判斷 | 份數、餐數、件數、包裝數等可數單位，即使題目沒寫「integer」，也要先判斷是否必須是整數。若必須是整數，LP 的小數解不能當作最終答案。 |

## 通用解題流程

1. 確認題目到底要求什麼（最小成本？最大利潤？還是最佳組合？）
2. 找出決策變數
3. 把文字轉成數學方向（至少、至多、恰好）
4. 統一單位
5. 判斷變數型態（連續 / 整數 / 0-1）
6. 盡量保留精確分數運算
7. 依題型套用對應的求解程序
8. 檢查可行性
9. 證明最佳性（對偶價格、上下界、列舉、最小割等）

## 題型專屬程序

飲食／飼料配方、轉運、TSP、最大流、設施選址（含容量限制、p-median、覆蓋模型）、生產組合、混合、生產與存貨規劃（含設置成本、缺貨回補、期末存貨）。每一類都有辨識方式、精確求解步驟、常見錯誤與「禁止的捷徑」。

## 在本網頁中的使用方式

原 Skill 的輸出規則是「每題只輸出一行 `{"id", "answer"}` JSON，不寫推理過程」，用於批次跑 benchmark。本網頁在 Skill 前加上一段使用說明：保留 Skill 的所有建模、整數判斷與驗證規則，但改為輸出結構化的完整解答，依序包含：

1. 問題理解
2. 模型元素（含整數／連續變數的判斷結果）
3. 目標函數與限制式
4. 模型類型與求解方法
5. 求解與驗證
6. 假設與限制
7. 結論

Skill 的原始內容沒有被修改；可在後端 `config.yaml` 的 `prompts.skills` 中新增或替換 Skill。
